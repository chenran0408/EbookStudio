# EbookStudio v0.8.0 对照与实测

## 优先级和验收标准

| 优先级 | v0.7.0 中复现的缺口 | 本版的通过条件 |
| --- | --- | --- |
| P0 | 桌面可以运行校对规则组和比较两个 EPUB。发布包公布的 11 个 MCP 工具及其内置指南均缺少这两项，握手还把服务版本写为 1.0.0。 | 已连接的 Agent 能发现对应工具、读取规则、预览每步改动、另存工程、比较修订前后并校验 EPUB。握手、CLI、状态和指南要能相互核对。 |
| P1 | 新用户在一台电脑录入规则后，界面能保存本机组，找不到交给同事或带去另一台电脑的操作。 | 导出正在编辑的组，再导入空白工作区；顺序、空格、正则与大小写设置保持一致。同名、取消及损坏文件要有明确结果。 |
| P1 | 一对实际修订稿有七项变化，对照窗口没有搜索框。有了目标句或文件名也需要逐行翻。 | 按 Ctrl+F 查改动行、章名或路径，可与类别组合；核对原版和修订版文字、封面图、空结果和重置。 |

Sigil 的已保存搜索支持分组和导出共享；calibre 的比较窗口可以在两版差异中查找文字。本版将这些操作接到现有规则组、检查点和 EPUB 对比窗口。问题依据程序走查和实际书稿复现，未组织独立的新用户测试。[Sigil 已保存搜索](https://github.com/Sigil-Ebook/sigil-user-guide/blob/master/src/OEBPS/Text/saved_searches.xhtml) · [calibre 版本对比](https://manual.calibre-ebook.com/diff.html)

## MCP 与说明

- v0.8.0 公布 14 个 MCP 工具。新增 `ebook_rule_groups`、`ebook_proofread` 和 `ebook_compare`；JSON 命令行使用同名操作并去掉 `ebook_` 前缀。
- 握手时提供工作流程，`ebook_guide({})` 直接返回随包指南，`ebook_status.version` 和握手中的服务版本均为 `0.8.0`。回归测试逐项比对服务实际发布的工具和指南参数表，检查是否漏列或重复列出。[Agent 指南](../agent.md) · [客户端接入说明](../Agent接入.md)

## 实测书稿

- 原创四页杂志的 PaddleOCR-VL-1.6 稿有八处署名斜杠识别为「 / 」。顺序应用两条规则，各命中八次，反序为零次与八次。预览不产生工程。使用过期预览、覆盖输入、默认覆盖已有输出均被拒绝。
- 从校订工程导出的 EPUB 保留四个目录目标、一幅逐像素相同的插图、两张表及十八个合并单元格。
- 另一对来自同一扫描件、独立导出的 EPUB 有七项差异。每页取两项，共四页，只有修订版第一章增加了校对句，另有四个章节文件改名。原版、修订版和输入工程的哈希保持一致。
- 用 475 章的年刊及已保存的修订版检查检索效果。按校对标记和「正文」组合筛选，找到涉及的两章和三处已知修改。年刊仅在本机用于验证。

## Windows 发布包

- 在最终桌面程序里导出尚未保存的两个步骤，再导入另一空白工作区。两步各命中八次，正则捕获组、大小写选项和首尾空格均保留。取消同名导入、导入无效正则都保留原规则和当前书稿。最终 Agent 读取同一工作区里的规则，按名称预览与直接传入导出 JSON 的步骤得到相同结果和预览标识。
- 用最终桌面程序搜索修订版新增的句子，命中右侧正文，未改动的相邻行不会误报。重置后重新显示全部七项。同一窗口能按「资源」和 `cover.jpg` 找到 calibre 添加的封面，左边提示原版没有，右边显示缩略图。未保存的书稿和比较输入均保留。
- 147 项自动化测试全部通过。便携 Agent 通过三个支持的 MCP 协议版本。由最终 Agent 导出的四页校订样书通过 EPUBCheck 5.4.0，**0 错误、0 警告**。
- Windows x64 ZIP 共 278,556,801 字节，已校验 1,958 个文件。SHA-256 为 `6a9aecc194c929fe7a845eff9b7c3c4f1cacf3d8c6d97493eb91b896c815ad4e`。[发布页](https://github.com/chenran0408/EbookStudio/releases/tag/v0.8.0) · [使用说明](../README.md)

## 仍可改进

整书替换仍按单个正文文本节点匹配。如果一个词的两个字被斜体等行内标签隔开，整词替换会跳过。书库的跨书全文检索和 OCR 批次续做也仍是桌面操作。对于经常把整批期刊交给 Agent 的用户，下一步优先考虑开放书库检索，再处理跨格式文字的校对。
